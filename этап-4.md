# ⚔️ Этап 4: Сетка 13×13, Fixed Swept AABB 40×40, Фракции и Game Juice

**Название:** Физика на фиксированном шаге, матрица коллизий фракций и Game Juice  
**Номер этапа:** 4  
**Дата выполнения:** 30 июля 2026

## Цель этапа
Создать физику на фиксированном шаге 60 Hz, матрицу коллизий фракций и эффекты сочности боя.

## Выполненные задачи

### 4.1 Карта и Сетка 13×13 (`src/systems/MapGridSystem.ts`)
- ✅ Реализована сетка 13×13 с клеткой 40×40px (логический буфер 520×520px)
- ✅ Типы тайлов: EMPTY, BRICK (1 HP), STEEL (вечная), BASE ([12][6]), WATER
- ✅ Методы: `getTile()`, `setTile()`, `damageTile()`, `isSolid()`, `getBaseCell()`
- ✅ Генерация тестовой карты: границы из стали, база в [12][6], кирпичные препятствия

### 4.2 Физика Fixed Swept AABB и Фракции (`src/systems/PhysicsSystem.ts`)
- ✅ Хитбокс 40×40 px, спрайт 32×32 по центру
- ✅ Swept AABB коллизии с соскальзыванием с углов в `fixedUpdate()`
- ✅ **Collision Matrix**: фильтрация проверок между фракциями (PLAYER, ENEMY, NEUTRAL, NONE)
- ✅ O(1) удаление объектов через swap-with-last (Zero-Allocation)
- ✅ Разделение осей X/Y для разрешения коллизий
- ✅ Ограничение мира (clamping к границам 520×520)

### 4.3 Пулы Объектов и Game Juice (`src/systems/JuiceSystem.ts`)
- ✅ **Screen Shake**: тряска экрана с затуханием (decay 0.9)
- ✅ **Hit Stop**: микро-заморозка 30-50 мс при попаданиях
- ✅ **Sprite Flash**: мигание при попадании (tint белый)
- ✅ **Floating Text Pool**: всплывающий текст с анимацией подъема + fade
- ✅ Object Pool для частиц и текстов (переиспользование без new в цикле)
- ✅ Интеграция в игровой цикл: `juice.update(deltaMS)` каждый рендер-кадр

### Дополнительно
- ✅ Тестовый танк с физикой в `main.ts` (демонстрация отскока от стен)
- ✅ Кнопка UI тестирует Juice систему (Shake + HitStop при клике)
- ✅ Проверка разрушения базы в `fixedUpdate()` → триггерит Game Juice

## Соблюдённые правила

### 14 Золотых Правил
- **Правило 1 (CanvasSource)**: Используется для текстур (из Этапа 2)
- **Правило 2 (Слои)**: Танк на TankLayer, UI на UILayer
- **Правило 4 (Fixed Timestep)**: Физика работает строго в `fixedUpdate(16.6мс)`
- **Правило 11 (Zero-Allocation)**: 
  - Нет `new` в циклах `fixedUpdate()` и `update()`
  - Переиспользуются `PIXI.Point` для временных расчетов
  - Swap-with-last для удаления из массива
- **Правило 13 (Dispose Pattern)**: Все системы имеют `destroy()` с полной очисткой

## Инструкция по ручной проверке

1. **Запуск приложения**:
   ```bash
   npm run dev
   ```
   Открыть `http://localhost:5173`

2. **Проверка рендера слоев**:
   - Зеленый квадрат (GroundLayer) — земля
   - Серый квадрат (WallLayer) — стена
   - Синяя кнопка (UILayer) — UI элемент

3. **Проверка физики танка**:
   - Танк должен двигаться и отскакивать от стен (520×520 логическая область)
   - При движении танк не должен проходить сквозь стены из стали/кирпича

4. **Проверка Juice системы**:
   - Кликнуть на синюю кнопку → должна быть тряска экрана (Shake) и микро-заморозка (HitStop 30мс)
   - В консоли должно быть `[UI] Button clicked!`

5. **Проверка коллизий с картой**:
   - В консоли разработчика проверить логи при ударе о стены
   - Танк должен "соскальзывать" с углов препятствий

6. **Проверка Zero-Allocation**:
   - Открыть Chrome DevTools → Performance → записать 5 секунд геймплея
   - Убедиться в отсутствии GC аллокаций в кадрах (Garbage Collector не должен срабатывать часто)

7. **Проверка Destroy Pattern**:
   - В консоли выполнить: `game.dispose()`
   - Убедиться в отсутствии утечек памяти (Memory tab в DevTools)

## Известные проблемы и замечания

### Потенциальные улучшения
1. **Spatial Hash Grid**: Для оптимизации коллизий между множеством объектов (>50) рекомендуется добавить Spatial Hash в будущем
2. **BitmapFont**: FloatingText сейчас использует `PIXI.Text` — заменить на `PIXI.BitmapText` после запекания шрифта
3. **Пули и Particles**: Пулы пуль и частиц объявлены в JuiceSystem, но требуют интеграции с EntityFactory (Этап 5+)
4. **Фракции снарядов**: Добавить проверку фракции снаряда при коллизии с танками (сейчас упрощенно)
